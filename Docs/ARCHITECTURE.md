# Prototype architecture

The Combat Lab uses intentionally narrow seams:

1. PlayerInputSource samples devices and emits PlayerIntent.
2. ThirdPersonMotor consumes intent and owns player locomotion, facing the actual horizontal travel vector while moving, stop-and-turn handling for sharp reversals, a takeoff-captured airborne speed ceiling, responsive speed-capped air steering, center-supported edge grounding, jump forgiveness, variable jump height, crouch collision, and overhead-clearance validation while exposing read-only state for presentation.
3. HumanoidAnimatorPresenter reads motor state and feeds an Animator without mutating gameplay movement. The Humanoid runs in-place with root motion disabled. A conventional planted walk is paired with a CC0 KayKit run retargeted into generated tactical jog/sprint clips. Walk travel and clip playback are raised proportionally to 1.85 m/s and 0.695x so the accepted foot path remains synchronized. Run generation removes source yaw, keeps the spine and gaze upright, tucks the upper arms while preserving their front/back swing, maintains positive foot separation, and phase-aligns the loop to enter on a planted contact without changing the accepted leg curves. Playback rates remain matched to the 4.6 m/s sprint target. Speed-blended standing and moving rise poses switch to fall from motor vertical velocity and leave the airborne state immediately on ground contact. The stationary tactical rest places the rear knee and heel at the floor, plants the forward sole, straightens the spine, and relaxes the arms. ShortSwordAttackPresenter runs on the Animator object: a fingers-only layer closes the grip and one uninterrupted torso/IK presentation traces the attack from high right to low left before returning to the current locomotion pose. Outside an attack there is no weapon-carry hand or elbow IK. The sword arm uses the complete authored walk/run motion, while the hand frame is held at a fixed 90-degree relationship to the animated forearm so the wrist cannot independently level or tip the blade. During wind-up, a distributed lower-arm twist and residual wrist roll present the broad blade in a slightly outward diagonal cutting plane; the committed strike holds that plane through contact and follow-through. In `LateUpdate`, the socket is reconstructed from the rotated index-to-little-knuckle grip axis. The leather grip is centered between wrist and knuckles, leaving the pommel below the fist and the guard/blade above it. The attack never mutates the motor or replaces the legs. ProceduralHumanoidPresenter remains only as an import-failure fallback.
4. CameraAimTarget converts look intent into a smoothed world-space aim transform, lowers with crouch, and clamps below detected ceilings; Cinemachine owns follow, shoulder framing, and collision presentation.
5. MeleeWeapon validates attack timing and submits DamageRequest values. The current prototype resolves overlap and damage synchronously when the attack is accepted; the visible hack remains presentation-only until creator testing establishes a deliberate anticipation/contact/recovery window.
6. DamageService resolves an IDamageable owner; Health is the only component that mutates health.
7. EnemyBrain retains replaceable enemy state logic but currently runs in passive training-dummy mode; EnemyTelegraphPresenter only visualizes state.
8. GameplayEventLog records meaningful combat state changes without making game systems depend on presentation.
9. LocomotionDebugOverlay provides an opt-in F8 live readout of motor speed, velocity-facing error, pose-facing error, head motion, foot spacing, foot height, hand spread, active clip weights, and full-scene recording status.
10. GameplayDiagnosticRecorder is a normally passive observer. F9 records natural free play and F10 adds an event-aligned screenshot marker. Schema-v2 captures correlate input, motor, physics, current/next Animator state, calibrated Humanoid pose and sole probes, crouch geometry, camera, weapon, damage, health, enemy state, and gameplay events into a versioned timestamped artifact bundle. Deterministic sample time is kept separate from wall time so screenshot or Editor stalls cannot distort simulation metrics. Each report also snapshots its source revision and effective motor, Animator, weapon, and camera configuration; an interrupted free-play capture is persisted as aborted rather than discarded.
11. CombatLabDiagnosticScenarioRunner uses the diagnostic override at PlayerInputSource—the existing input ownership seam—to drive a frame-locked full-scene movement and combat suite through production code. It is an Update-driven transaction: the named phase and intent are committed before production input and simulation, then the recorder observes the result in `LateUpdate`. Independent right and left sprint turns prevent a directional bias from hiding inside a combined test. Combat phases retain explicit slash wind-up, contact, follow-through, and recovery screenshots in addition to attack/damage event records. A run can pass only after every required phase completes exactly once and a completion event is observed; early Play-mode exit, timeout, Unity error, or explicit cancellation records an abort instead of accepting a partial run.
12. The Editor diagnostics orchestrator manages Play mode, source capture, errors, batch exit status, creator reviews, and baseline comparisons. Baseline promotion requires a completed, functionally passing current-schema deterministic run plus a persisted **Accepted** review that names that exact run. No schema-v2 baseline is currently accepted.
13. LocomotionDiagnosticsRunner immutably evaluates the existing Humanoid Animator controller at 60 samples per gait and writes machine-readable telemetry plus 16-pose front/side/rear contact sheets. It never regenerates the assets it measures.
14. CombatLabSceneBuilder creates the disposable greybox scene reproducibly and attaches the passive recorder.

This is multiplayer-aware rather than multiplayer-built. Input, requests, authoritative owners, stable IDs, and event records create future evaluation seams. No current code promises that multiplayer conversion will be automatic.

## Next proof sequence

1. Playtest the authored-animation checkpoint and tune model scale, clip cadence, transitions, and the tactical crouch silhouette.
2. Add aim-relative locomotion with independent upper-body facing and readable strafe/backpedal presentation around the held short sword.
3. Refine the provisional hack into the first deliberate melee interaction with animation-aligned anticipation, contact, and recovery.
4. Add one valuable pickup, a clear extraction zone, death, and a small consequence.
5. Test a reduced Weapon Grid with only a few artifacts and one meaningful tradeoff.
6. Assemble a raid from authored chunks with stable connectors and a deterministic seed.
7. Add pseudo-player NPC behavior only after combat spaces and extraction pressure exist.
